# mail-notifier

お名前.com のメールボックスを GitHub Actions が5分おきに IMAP で確かめ、
指定した差出人からの新着メールを Discord に知らせる。PC を付けておく必要はない。

- メールは**読み取り専用**で開く(既読にならない・消さない)。本文は読まない。
- 通知の中身は「差出人・件名・日時」だけ。ログにもメールの内容は出さない。
- 初回は、いまあるメールを通知せず「ここから先」を見張る。
- どこまで知らせたかは `state.json`(最後に見たメールの番号)に記録し、Actions が書き戻す。
- 失敗したら Actions が赤になり、GitHub からメールで知らせが来る。

## 準備

1. **Discord の Webhook URL** を用意する(チャンネルの設定 → 連携サービス → ウェブフック)。
2. **IMAP の接続先**を確かめる。Webメールが `webmailXXXX.onamae.ne.jp` なら、受信サーバーは
   `mailXXXX.onamae.ne.jp`。
3. このフォルダを GitHub のリポジトリにして push する。定期実行は、Secrets を入れ終えるまで止めておく
   (設定がないまま動くと5分おきに失敗のメールが来るため)。
4. リポジトリの Settings → Secrets and variables → Actions → **New repository secret** で次を登録する。

| 名前 | 中身 | 必須 |
|---|---|---|
| `IMAP_HOST` | 受信サーバー名 | ○ |
| `IMAP_USER` | 見張るメールアドレス(ログイン名) | ○ |
| `IMAP_PASSWORD` | そのメールのパスワード | ○ |
| `WATCH_FROM` | 知らせてほしい差出人。複数はカンマ区切り(下の「差出人の書き方」) | ○ |
| `DISCORD_WEBHOOK_URL` | Discord の Webhook URL | ○ |
| `IMAP_PORT` | 993 以外のとき | |
| `IMAP_FOLDER` | INBOX 以外のとき | |

5. Actions のタブ → `check-mail` → **Enable workflow**(止めてあれば)→ **Run workflow** で一度手で動かす。
   1回目は「基準を UID ○○ にしました」と出れば成功(この回は通知しない)。
6. 見張る差出人から試しにメールを送り、次の回(最大で5〜十数分後)に Discord に届くか確かめる。

## 差出人の書き方(`WATCH_FROM`)

`*` は「@ 以外の0文字以上」。大文字小文字は区別しない。カンマで区切って並べる。

| 書き方 | 一致するもの |
|---|---|
| `boss@x.jp` | その人だけ(`xboss@x.jp` は別) |
| `*@x.jp` | x.jp のすべて(サブドメイン `a@sub.x.jp` は含まない) |
| `*yamada*@*` | @ より前に yamada を含む人(ドメインは問わない) |

すべてに一致する `*@*` は、大量の通知を防ぐため無視する。

## 注意

- **遅れ**: GitHub の定期実行は混んでいると遅れる・抜けることがある。届くまで数分〜数十分かかることがある。
- **費用**: 公開リポジトリなら無料。非公開リポジトリは無料枠が月2000分で、5分おきだと超える
  (1回ごとに1分として数えられ、月に約8600回になる)。非公開にするなら、
  `.github/workflows/check-mail.yml` の cron を `*/30 * * * *`(30分おき)などにする。
- **公開リポジトリでも** Secrets の中身は見えず、ログにも伏せ字で出る。ただし、ほかの人に見えるのは
  コード・`state.json`(メールの番号だけ)・実行の記録。
- **60日の休止**: 公開リポジトリは、60日間なにも動きがないと定期実行が止まる。
  新着メールがあれば `state.json` の書き戻しで動きが出るが、止まったら Actions の画面から有効にし直す。
- **差出人の偽装**: 差出人の欄は書き換えられるので、なりすましのメールにも通知は来る(通知だけなので害は小さい)。
